# Parameter Optimization Insights

## 2026-06-30

- The global robust score is useful for ranking parameter sets, but old guardrails like "do not regress Cunk" can reject globally better configs. Current optimizer default is score-only selection; guarded selection remains available for conservative checks.
- `espnet_ecapa_wavlm_joint` produced the strongest cached score so far, but it is too VRAM-heavy for the live path on an 8 GB GPU with `large-v2` running at the same time.
- Measured provider VRAM matters more than provider latency for live usability. `espnet_ecapa_wavlm_joint` measured about 2854 MiB peak VRAM delta; `speechbrain_ecapa` measured about 305 MiB.
- A provider stack must be judged by summed loaded provider VRAM, not by each provider independently. Example: two individually safe 1200 MiB providers can still exceed a 2048 MiB stack budget.
- Provider weights do not materially reduce model VRAM, because all providers in a stack still load. Weight only changes embedding contribution.
- Focused local mutation improves a good candidate, but quickly gets stuck in local minima. Example: the heavy WavLM candidate improved from 0.763475 to 0.775384 over generations, then plateaued.
- Search must keep provider-stack variety high enough. If we only refine the current best provider stack, we can miss a different provider combination that needs different clustering thresholds.
- For VRAM-capped search, use broad random search plus provider-diverse final reranking before focused refinement. Do not jump too early to single-stack local refinement.
- Current best <= 2048 MiB stack search result after a first pass: `jungjee_rawnet3=1 + speaker3d_campplus=0.75`, score 0.742764 after local refinement. This is worse than the heavy WavLM result but far more live-compatible.
- The optimizer should record provider VRAM metadata and excluded providers in each output JSON so later results are interpretable.
- The optimizer now supports a stack-level VRAM budget. In the 2048 MiB run, `espnet_ecapa_wavlm_joint` was excluded and all generated/evaluated stacks stayed under budget.
- A provider-diverse 2048 MiB run (`optimizer_vram2gb_diverse_2500_seed4040.json`) tested broader stack families and produced best score 0.731340 with `espnet_rawnet3=0.5 + wespeaker_resnet34_lm_onnx=1 + speechbrain_ecapa=1` at about 927 MiB measured provider VRAM. This did not beat the focused capped best, so do not replace the current <=2GB live candidate yet.
- The focused capped best remains `jungjee_rawnet3=1 + speaker3d_campplus=0.75`, score 0.742764, about 819 MiB measured provider VRAM. This is the best live-compatible <=2GB candidate found so far.
