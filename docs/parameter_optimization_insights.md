# Parameter Optimization Insights

## 2026-06-30

- The global robust score is useful for ranking parameter sets, but old guardrails like "do not regress Cunk" can reject globally better configs. Current optimizer default is score-only selection; guarded selection remains available for conservative checks.
- `espnet_ecapa_wavlm_joint` produced the strongest cached score so far, but it is too VRAM-heavy for the live path on an 8 GB GPU with `large-v2` running at the same time.
- Measured provider VRAM matters more than provider latency for live usability. `espnet_ecapa_wavlm_joint` measured about 2854 MiB peak VRAM delta; `speechbrain_ecapa` measured about 305 MiB.
- A provider stack must be judged by summed loaded provider VRAM, not by each provider independently. Example: two individually safe 1200 MiB providers can still exceed a 2048 MiB stack budget.
- Provider weights do not materially reduce model VRAM, because all providers in a stack still load. Weight only changes embedding contribution.
- Focused local mutation improves a good candidate, but quickly gets stuck in local minima. Example: the heavy WavLM candidate improved from 0.763475 to 0.775384 over generations, then plateaued.
- Search must keep provider-stack variety high enough. If we only refine the current best provider stack, we can miss a different provider combination that needs different clustering thresholds.
- For VRAM-capped search, use broad random search plus provider-diverse final reranking before focused refinement. Do not jump too early to single-stack local refinement.
- Current best <= 2048 MiB stack search result after a first pass: `jungjee_rawnet3=1 + speaker3d_campplus=0.75`, score 0.742764 after local refinement. This is worse than the heavy WavLM result but far more live-compatible.
- The optimizer should record provider VRAM metadata and excluded providers in each output JSON so later results are interpretable.
- The optimizer now supports a stack-level VRAM budget. In the 2048 MiB run, `espnet_ecapa_wavlm_joint` was excluded and all generated/evaluated stacks stayed under budget.
- A provider-diverse 2048 MiB run (`optimizer_vram2gb_diverse_2500_seed4040.json`) tested broader stack families and produced best score 0.731340 with `espnet_rawnet3=0.5 + wespeaker_resnet34_lm_onnx=1 + speechbrain_ecapa=1` at about 927 MiB measured provider VRAM. This did not beat the focused capped best, so do not replace the current <=2GB live candidate yet.
- The focused capped best remains `jungjee_rawnet3=1 + speaker3d_campplus=0.75`, score 0.742764, about 819 MiB measured provider VRAM. This is the best live-compatible <=2GB candidate found so far.

- Post-push experiments found a no-canonical postprocess upper candidate at `global_robust_score=0.821240` using the current 5-provider stack with `speechbrain_resnet=0.35`, prototype reassignment, and conservative profile merging. This is not yet promoted because it was measured as a cached postprocess, not as the online live path.
- Final-centroid profile merging alone improved only to about `0.818564`. It fixes oversplitting in `F2-2RBi1qzY` and `1NBVQB-Srpw`, but it cannot solve the three hard mixed-profile videos.
- Local temporal smoothing and neighbor reassignment did not beat the prototype/merge candidate. The best neighbor-reassignment run reached about `0.818892`.
- A synthetic `spatial_stereo` provider from left/right energy, correlation, and mid/side features did not improve the score at any tested weight from `0.00` to `2.00`. Diagnostic pan means were near zero for the current hard videos, so stereo position is not a useful signal for this corpus.
- Focused random search on the three limiting videos (`WNZn37Uc700`, `KdOXM3I_5hk`, `acbnyagl8jo`) barely moved their objective (`~0.7919` to `~0.7924`) and kept the same 5-provider family. This suggests the current sentence embeddings/window clips, not only global parameter selection, are the bottleneck.
- An offline cosine k-means diagnostic using the true canonical speaker count scored worse than the online clustering path (`global_robust_score=0.739640`). This indicates the embedding space is not cleanly separable by simple global clustering on the cached sentence clips.
- Allowing prototype reassignment on longer/high-confidence rows improved the best cached replay to `global_robust_score=0.829061`, `mean_video_score=0.851914`, `worst_video_score=0.799829`, and `bottom3_mean_video_score=0.803732`. The best postprocess candidate uses `max_per_profile=32`, `prototype_min_duration=0.15`, `top_k=12`, `centroid_blend=0.555`, `max_reassign_duration=8.0`, `min_delta=0.108`, and the same safe profile merge rule.
- Direct provider-weight random search under the all-row prototype rule did not beat the local-refined stack. The best remained `espnet_ecapa_wavlm_joint=0.74 + jungjee_rawnet3=0.99 + wespeaker_campplus=0.34 + speechbrain_resnet=0.35 + resemblyzer=0.12`.
- Recutting embedding audio to strict `first_word_start..last_word_end` windows for the three hard videos made results worse (`bottom3-only global_robust_score=0.781799` versus `0.802561` for the original windows under the same all-row prototype candidate). Combining original and tight embeddings as dual crops also selected `tight_scale=0.0`, so tight word-only crops should not be pursued further without a different crop design.
- Follow-up attempts to break the `0.829061` plateau did not improve global score: internal profile subcluster reassignment, broader safe-merge threshold sweeps, HMM/Viterbi sequence smoothing over prototype emissions, and iterative prototype self-training all converged back to the same best score or regressed. These outputs are `runtime\optimization\subcluster_reassign_experiment_500.json`, `runtime\optimization\merge_rule_refine_600.json`, `runtime\optimization\hmm_sequence_smoothing_260.json`, and `runtime\optimization\iterative_prototype_reassign_grid.json`.
- Allowing subclusters to split into new synthetic profiles also failed to beat `0.829061`; the speaker-count penalty plus mixed cluster quality canceled any duration gains. The output is `runtime\optimization\subcluster_split_experiment_600.json`.
- A text/time-aware turn-taking HMM gave a small but reproducible improvement to `global_robust_score=0.829815`, `mean_video_score=0.852801`, `worst_video_score=0.800507`, and `bottom3_mean_video_score=0.804147`. It uses prototype emission scores plus local turn cues from short/backchannel text, dialogue gaps, and current-label bias; no canonical labels or video-specific rules are used. The best output is `runtime\optimization\turn_taking_hmm_local_refine_350.json`.
